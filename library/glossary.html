GLOSSARY — Domino Data Lab (Enterprise AI Platform)

Study glossary for the Domino Data Lab pack. Definitions follow the source ledger. They are not a claim that the study day was completed.

Definitions below are study definitions tied to the source ledger. The one-day session has not been sat, so none of these are marked as earned in practice.

Term Definition Block
Model A trained function that maps inputs to predictions or generations. Training produces it. Inference uses it. 1
Training Fitting parameters on data. Compute-heavy, usually a Job or a Workspace session. 1
Inference Running a trained model on new inputs. Serving is inference offered as an endpoint or an App. 1
Experiment A recorded attempt: code, Environment, hardware, data, and parameters, plus metrics. 1
Registry The catalog of models you intend to reuse or ship. Domino's is MLflow-based. [S4] 1
Serving Making a model callable. In Domino: Model API, App, or export to another host. [S7] [S8] 1
Endpoint An HTTP interface to a packaged model. Domino packages Flask (Python) or Plumber (R). [S7] 1
MLOps The practice of taking models from a notebook into a governed, repeatable lifecycle. Nearby papers discuss it; they are not a Domino eval. [S14] 1
Governance Review, lineage, access, and change control around models and apps. Model Sentry is one HITL step. [S7] 1
Lineage What produced this artifact: code, Environment revision, workspace settings, datasets. Model cards store it. [S4] 1
Reproducibility Ability to rebuild the same run from the recorded context. Albertoni 2023 is nearby terminology, not a Domino eval. [S15] 1
Audit trail The durable record a reviewer can open later. The registry and model card are the intended trail. [S4] 1
Kubernetes Cluster of machines that schedule containers (pods) from images. Domino is Kubernetes-native (Helm). [S2] 1
Cluster A Kubernetes cluster. Control plane and data plane can be different clusters. [S2] [S3] 1
Pod An ephemeral set of containers. Workspaces, Jobs, Apps, and endpoints run as pods. [S2] 1
Image A Docker image. An Environment is Domino's abstraction over one. [S5] 1
Domino Data Lab Enterprise AI / MLOps platform: workspaces, compute, datasets, experiments, registry, endpoints, Apps, governance. Product home [S10]; contract is the docs. 1
Project The unit of work. Files, Environments, datasets, experiments, models, and Apps live here. [S1] 1
Workspace Hosted IDE (Jupyter, JupyterLab, VS Code, RStudio, SAS, MATLAB, Cursor) on a hardware tier. [S6] 1
Hardware tier The size and type of machine a Workspace, Job, App, or endpoint requests. Can target a data plane. [S6] [S8] 1
Environment Docker-image abstraction. DSE (Domino Standard Environment) vs DME (Domino Minimal Environment). Every Workspace, Job, App, and Model boots a container. [S5] 1
Environment revision A rebuild of that image after an edit. The card should name the revision that trained the model. [S4] [S5] 1
Dataset Versioned data Domino tracks for a Project. Remote data planes historically lacked Datasets. [S3] 1
Job Non-interactive run of Project code on a hardware tier. The path from a Workspace to automation. [S6] 1
Experiment tracking Recording runs and metrics, typically through the MLflow-based manager. [S4] 1
Model registry MLflow-based catalog of models. Not the IDE. [S4] 1
Model card Lineage record: code, Environment, workspace settings, datasets. Reconstruct the run from the card, not from memory. [S4] 1
Model API Project files packaged as Flask or Plumber and hosted as an endpoint. [S7] 1
App HTTP app (Dash, Flask, Streamlit, Shiny, or any HTTP) served from a Project, port 8888. [S8] 1
App Hub Marketing name for scaling AI-powered apps to users. The contract is Publish Apps [S8], not the homepage alone [S10]. 1
Launchpad Where users find published Apps. Distinct from a Project's Deployments list. [S8] 1
Control plane UI, API, metadata, orchestration. Node.js/React UI, Secrets Vault, API, RabbitMQ, Identity, MongoDB/PostgreSQL, Experiment Manager, Image Builder, Model Registry. [S2] 2
Data plane Where work runs: data plane agent, Cluster Autoscaler, Workspaces, Apps, endpoints, Jobs, distributed clusters as ephemeral pods. [S2] 2
Local data plane Data plane in the control-plane cluster. Full feature set historically. [S3] 2
Remote data plane Data plane in another cluster, cloud, region, or on-prem. Check the installed version for Model APIs, Apps, Datasets. [S3] 2
Nexus Hybrid: one control plane, many data planes. Optional add-on. Prefer [S3] over the product page [S11]. 2
Data plane agent Component that lets the control plane schedule work on that plane. [S2] 2
Secrets Vault Control-plane store for credentials. Not your laptop env file. [S2] 2
Identity How people sign in. Docs next-steps include Keycloak. [S2] 2
Environment Image Builder Control-plane service that rebuilds Environment images. [S2] 2
Model Sentry Human-in-the-loop review before production. [S7] 5
Model Monitoring Drift and performance after deploy. [S7] 5
Deployment offerings Cloud (managed SaaS), self-managed VPC, on-prem, optional Nexus data planes. [S9] 5
HPA Horizontal Pod Autoscaler for Apps. Always at least one pod. [S8] 7
Port 8888 The port a Domino App must serve. [S8] 7
Databricks Lakehouse + Unity Catalog + MLflow. Wins when the work already lives on that lake. Debate 5. 7
SageMaker AWS managed train/serve. Wins when the account is already AWS-native and endpoints already exist. Debate 6. 7
OpenShift AI Red Hat Kubernetes ML platform. Wins when the estate is already OpenShift. 7
Kubeflow Open-source Kubernetes ML stack. Wins when the team will operate CRDs themselves. 7
Dataiku Visual + governed analytics workbench. Wins when the users are analysts, not IDE-first scientists. 7
IL5 DoD Impact Level 5. Marketing says Domino "is deployed in DoD IL5 environments" [S10]. That sentence is not a DISA PA or an ATO. 5
ATO Authorization to Operate for this program. A vendor logo does not grant it. Debate 3. 5
Provisional Authorization DISA PA for a named cloud service offering. This pack has no PA letter on the ledger. 5
SOC 2 / HIPAA / ISO 27001 Compliance program claims on [S10]. Evidence of a program, not of this lab. 5
21 CFR Part 11 Marketing "supports" language [S10]. Not a validation package for this tenant. 5
Briefing percentages 50% lifecycle, 6× development, 40% infra, 75% onboarding on [S10]. Not an SLA. 5
System of record Code + Environment + hardware + datasets + parameters that reconstruct a run. The product claim in Debate 1. [S4] 2
Any-tool claim Domino hosts many IDEs and frameworks. Hosting is not zero lock-in. Debate 2. [S1] [S5] 2
Reproducibility theater Tracking files without pinning Environment revision and data version. Block 5 trap. 5
Idle GPU A Workspace left open on a GPU tier. Someone's budget. [S6] 5

NotebookLM exports, when they arrive after W8, are secondary. The ledger wins if a report disagrees.
