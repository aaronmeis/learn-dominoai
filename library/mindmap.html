Domino Data Lab

  • Day outcome: By the end of the day, explain Domino from zero and sketch one governed model lifecycle you could defend in a design review. The sketch names what a project contains, where compute runs, where the system of record lives, and when Databricks, SageMaker, OpenShift AI, Kubeflow, or Dataiku is the better placement. Success is a short written explanation plus that sketch, with one named failure mode.
  • Depth: Working fluency across the platform. Enough to sketch project → experiment → registry → endpoint or App Hub and say why the platform claims that path is reproducible. Later day: App Hub, hybrid control plane, or IL5.
  • Prior knowledge: Assume zero. Define a model, training versus inference, an experiment, a registry, serving, MLOps, governance, and Kubernetes at outline level before any Domino term.
  • Boundaries: Must include: what Domino is, project and workspace, Environment and hardware tier, datasets, jobs and experiments, model registry and model cards, endpoints / Model APIs, App Hub, reproducibility and lineage, hybrid / on-prem / cloud at sketch level, and when not to use Domino.

Out of scope: production deploy, tenant lab, packet capture, treating IL5 / HIPAA / SOC 2 as authorization, building custom Environments as a lab, multi-week academy.

  • Core concepts (define these without Domino first)
  • A model, training versus inference, an experiment
  • A registry, serving / an endpoint, MLOps
  • Governance, lineage, reproducibility, an audit trail
  • Kubernetes at outline level (cluster, pod, image)
  • Then Domino: a Project as the unit of work
  • Workspace (Jupyter, RStudio, VS Code, SAS, MATLAB, Cursor) on a hardware tier
  • Environment (the image / packages the workspace boots)
  • Dataset, Job, Experiment tracking
  • Model registry and model card
  • Model API / endpoint, and App Hub as the application surface
  • Mental models
  • System of record: code + data + Environment + parameters should reconstruct the run
  • Control plane versus data plane: who schedules work versus where bytes and GPUs live
  • Hybrid: the same Project story on-prem, in a cloud, or both
  • Model factory versus App Hub: build and govern models versus scale apps to users
  • "Any tool" is a claim: the platform hosts IDEs and frameworks; it does not erase their semantics
  • Comparison set: Databricks, SageMaker, OpenShift AI, Kubeflow, Dataiku. Each wins a different job.
  • Active practice targets
  • On paper, define model, experiment, registry, serving, and lineage in your own sentences
  • Sketch one lifecycle: Project → Workspace / Job → Experiment → Registry → Endpoint or App Hub
  • Annotate the sketch with where compute runs and what is recorded
  • From official docs, label one page as architecture and one page as a compliance claim
  • Teach-back angle
  • Five minutes to someone who has trained a notebook model on a laptop
  • Must include one sentence on why a system of record is the product, not the IDE
  • Must include one sentence on a job Domino should refuse (or lose to a competitor)
  • Edge cases / traps
  • Reproducibility theater: tracking files without pinning Environment and data
  • Idle GPU / hardware-tier cost while a workspace sits open
  • "Any tool, no lock-in" versus the platform as the place work actually lives
  • Exporting a model to SageMaker / Snowflake / Databricks does not make those platforms Domino
  • IL5 / HIPAA / SOC 2 / 21 CFR Part 11 pages are evidence of a program, not an authorization for this lab
  • Vendor percentages (lifecycle time, 6×, 40% infra) are briefing lines, not an SLA
  • Application task
  • Written explanation from zero, plus one defended lifecycle sketch
  • The sketch names Project contents, compute, system of record, and the tool you would not pick
  • Name one failure mode (reproducibility gap, cost, wrong platform, or compliance overclaim)
  • Claims and debates (required after the ledger)
  • At least three live debates with warrants and designed counter-evidence (research-craft / NEXUS 72)
  • Default competitor voices: Databricks, SageMaker, OpenShift AI, Kubeflow, Dataiku
  • Designed tests stay unrun (no tenant). Desk tests can run from docs. Lab waits for an install / tenant GO
